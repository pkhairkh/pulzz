# pulzZ SDK Proposal

**Version:** 0.1-draft
**Date:** 2026-08-13
**Status:** Proposal — not yet implemented

---

## 1. Motivation

The pulzZ repo currently exposes a Rust-native API (`ServerSession`, `ClientSession`,
`emit_event`, `emit_batch`, `apply_record`). This is usable from Rust but not from
the target deployment surfaces: browsers (WASM/JS), native C/C++ applications,
Python services, Go backends, or mobile (iOS/Android).

This proposal defines a **multi-target SDK** with:
- A **Rust API** (the canonical implementation)
- A **C ABI** (`extern "C"`) for FFI to C/C++/Go/Python/Node
- A **WASM/JS binding** for browser and Node.js
- A **Python binding** (via PyO3 or cffi)
- A **Go binding** (via cgo)

All backends share the same wire protocol, PQC handshake, and batch envelope format.

---

## 2. Design principles

1. **One wire, many bindings.** The `shared_protocol` crate is the single source of truth. All bindings wrap it; none reimplement it.
2. **C ABI is the root FFI.** Every non-Rust binding (JS, Python, Go) goes through the C ABI. This means: one header file, one shared library, consumed by all.
3. **Backend parity.** The same `Client` API works over WebSocket, TCP, QUIC, WebTransport, and UDP datagram. The caller picks the carrier; the SDK handles the rest.
4. **Safety first.** All C ABI functions return `pulzz_result_t` (error code). No panics cross the FFI boundary. All pointers are checked for null. All buffers carry explicit lengths.
5. **Zero-copy where possible.** The C ABI accepts `pulzz_slice_t { ptr, len }` for input buffers and `pulzz_mut_slice_t { ptr, len, cap }` for output buffers. No string copying for hot paths.
6. **Async is explicit.** The C ABI exposes a poll-based API (`pulzz_session_poll`, `pulzz_session_recv`) rather than callbacks. Higher-level bindings (JS, Python) provide async/await.

## 5. Rust SDK API (idiomatic)

The `sdk` crate provides a high-level, ergonomic API that wraps `server` and `client`.

### 5.1 Client

```rust
use pulzz_sdk::{PulzzClient, CarrierKind, SecurityProfile};

// Build and connect
let mut client = PulzzClient::builder()
    .carrier(CarrierKind::WebSocket)
    .security(SecurityProfile::PqMutualV1)
    .batch_size(50)                    // enable batching
    .connect("ws://example.com:8080")
    .await?;

// Send single item
let record = client.send(ItemId(1), &payload).await?;

// Send a batch (amortizes AEAD + transport overhead)
client.send_batch([
    (ItemId(1), &payload_1),
    (ItemId(2), &payload_2),
    (ItemId(3), &payload_3),
]).await?;

// Receive (async stream of records)
while let Some(record) = client.recv().await? {
    let item = record.decode()?;
    println!("got item {}: {} bytes", item.id.0, item.bytes.len());
}

// Disconnect cleanly
client.close().await?;
```

### 5.2 Server

```rust
use pulzz_sdk::{PulzzServer, CarrierKind, SecurityProfile};

let mut server = PulzzServer::builder()
    .carrier(CarrierKind::QuicStream)
    .security(SecurityProfile::PqMutualV1)
    .bind("0.0.0.0:4433")
    .await?;

while let Some(mut session) = server.accept().await? {
    tokio::spawn(async move {
        while let Some(record) = session.recv().await? {
            // Process record...
            session.send(ItemId(1), &response).await?;
        }
    });
}
```

### 5.3 BatchBuilder

```rust
use pulzz_sdk::BatchBuilder;

let batch = BatchBuilder::new()
    .item(ItemId(1), SourceKind::Json, &json_payload_1)
    .item(ItemId(2), SourceKind::Json, &json_payload_2)
    .item(ItemId(3), SourceKind::Text, &text_payload_3)
    .build();

client.send_batch_raw(batch).await?;
```

### 5.4 Config types

```rust
pub enum SecurityProfile {
    /// ML-KEM-768 + ML-DSA-65 (full PQ mutual auth)
    PqMutualV1,
    /// ML-KEM-768 only (PQ KEM, no signatures)
    PqSimpleV1,
    /// X25519 + Ed25519 (classical, for testing only)
    ClassicRef1,
}

pub enum CarrierKind {
    WebSocket,       // browser + native
    Tcp,             // native only
    QuicStream,      // native only (quinn)
    QuicDatagram,    // native only
    WebTransport,    // browser + native
    UdpDatagram,    // native only
}

pub struct CompressionConfig {
    pub enabled: bool,              // false on WASM
    pub batch_threshold: usize,     // min items to batch (default: 10)
    pub zstd_level: i32,            // default: 3
}

pub struct ClientConfig {
    pub security: SecurityProfile,
    pub carrier: CarrierKind,
    pub compression: CompressionConfig,
    pub batch_size: Option<usize>,  // None = per-item, Some(n) = batched
    pub timeout_ms: u64,
}
```

## 6. C ABI (`extern "C"`)

The `ffi` crate exposes a stable C ABI. All functions use the `pulzz_` prefix.
All types are opaque pointers. All return codes are `pulzz_result_t`.

### 6.1 Core types

```c
// pulzz.h

#include <stddef.h>
#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

// --- Opaque handles ---
typedef struct pulzz_client_t pulzz_client_t;
typedef struct pulzz_server_t pulzz_server_t;
typedef struct pulzz_session_t pulzz_session_t;
typedef struct pulzz_batch_t pulzz_batch_t;

// --- Result codes ---
typedef enum {
    PULZZ_OK = 0,
    PULZZ_ERR_INVALID_ARG = 1,
    PULZZ_ERR_INVALID_STATE = 2,
    PULZZ_ERR_CONNECTION_FAILED = 3,
    PULZZ_ERR_HANDSHAKE_FAILED = 4,
    PULZZ_ERR_COMPRESSION_FAILED = 5,
    PULZZ_ERR_TIMEOUT = 6,
    PULZZ_ERR_BUFFER_TOO_SMALL = 7,
    PULZZ_ERR_INTERNAL = 99,
} pulzz_result_t;

// --- Carrier kinds ---
typedef enum {
    PULZZ_CARRIER_WEBSOCKET = 0,
    PULZZ_CARRIER_TCP = 1,
    PULZZ_CARRIER_QUIC_STREAM = 2,
    PULZZ_CARRIER_QUIC_DATAGRAM = 3,
    PULZZ_CARRIER_WEBTRANSPORT = 4,
    PULZZ_CARRIER_UDP_DATAGRAM = 5,
} pulzz_carrier_kind_t;

// --- Security profiles ---
typedef enum {
    PULZZ_SECURITY_PQ_MUTUAL_V1 = 0,    // ML-KEM + ML-DSA
    PULZZ_SECURITY_PQ_SIMPLE_V1 = 1,    // ML-KEM only
    PULZZ_SECURITY_CLASSIC_REF1 = 2,    // X25519 (testing only)
} pulzz_security_profile_t;

// --- Slice types (zero-copy) ---
typedef struct {
    const uint8_t* ptr;
    size_t len;
} pulzz_slice_t;

typedef struct {
    uint8_t* ptr;
    size_t len;
    size_t cap;
} pulzz_mut_slice_t;

// --- Config ---
typedef struct {
    pulzz_carrier_kind_t carrier;
    pulzz_security_profile_t security;
    uint32_t batch_size;           // 0 = per-item, >0 = batch size
    int32_t zstd_level;            // 0 = disabled, 3 = default
    uint64_t timeout_ms;
} pulzz_config_t;
```

### 6.2 Client API

```c
// --- Lifecycle ---

// Create a client (returns opaque handle). Caller owns the handle.
pulzz_result_t pulzz_client_new(
    const pulzz_config_t* config,
    pulzz_client_t** out_client
);

// Connect to a server. Returns PULZZ_OK on success.
// `url` is a null-terminated C string (e.g. "ws://host:port").
pulzz_result_t pulzz_client_connect(
    pulzz_client_t* client,
    const char* url
);

// --- Send ---

// Send a single item (per-item emission).
pulzz_result_t pulzz_client_send(
    pulzz_client_t* client,
    uint64_t item_id,
    pulzz_slice_t payload
);

// --- Batch send ---

// Create a batch builder.
pulzz_result_t pulzz_batch_new(
    pulzz_batch_t** out_batch
);

// Add an item to the batch.
pulzz_result_t pulzz_batch_add(
    pulzz_batch_t* batch,
    uint64_t item_id,
    uint8_t source_kind,    // 0=text, 1=json, 2=binary, 3=image
    pulzz_slice_t payload
);

// Send the batch. Consumes and frees the batch handle.
pulzz_result_t pulzz_client_send_batch(
    pulzz_client_t* client,
    pulzz_batch_t* batch
);

// --- Receive ---

// Poll for incoming records. Returns PULZZ_OK if a record is available.
// The record payload is written to `out_payload` (caller-allocated buffer).
// If no record is available, returns PULZZ_ERR_TIMEOUT.
pulzz_result_t pulzz_client_recv(
    pulzz_client_t* client,
    pulzz_mut_slice_t* out_payload,
    uint64_t* out_item_id,
    uint32_t timeout_ms
);

// --- Lifecycle ---

// Close the connection and free the client handle.
pulzz_result_t pulzz_client_close(
    pulzz_client_t* client
);

// Free the client handle (without graceful close).
void pulzz_client_free(
    pulzz_client_t* client
);
```

### 6.3 Server API

```c
// --- Lifecycle ---

pulzz_result_t pulzz_server_new(
    const pulzz_config_t* config,
    pulzz_server_t** out_server
);

pulzz_result_t pulzz_server_bind(
    pulzz_server_t* server,
    const char* addr          // e.g. "0.0.0.0:4433"
);

// Accept a new session (blocking).
pulzz_result_t pulzz_server_accept(
    pulzz_server_t* server,
    pulzz_session_t** out_session,
    uint32_t timeout_ms
);

// --- Session ---

pulzz_result_t pulzz_session_send(
    pulzz_session_t* session,
    uint64_t item_id,
    pulzz_slice_t payload
);

pulzz_result_t pulzz_session_recv(
    pulzz_session_t* session,
    pulzz_mut_slice_t* out_payload,
    uint64_t* out_item_id,
    uint32_t timeout_ms
);

pulzz_result_t pulzz_session_close(
    pulzz_session_t* session
);

void pulzz_session_free(
    pulzz_session_t* session
);

void pulzz_server_free(
    pulzz_server_t* server
);
```

### 6.4 Error handling

```c
// Get the last error message (thread-local). Returns NULL if no error.
// The returned string is valid until the next pulzz_* call on the same thread.
const char* pulzz_last_error(void);
```

### 6.5 Versioning

```c
// Semantic version of the ABI.
uint32_t pulzz_abi_version(void);  // packed: major<<16 | minor<<8 | patch

// Human-readable version string.
const char* pulzz_version_string(void);
```

## 7. WASM/JS binding

The `bindings/wasm` crate uses `wasm-bindgen` to expose the SDK to JavaScript.

### 7.1 JS API

```typescript
// pulzz.js (auto-generated by wasm-bindgen)

export class PulzzClient {
  constructor(config: PulzzConfig);
  connect(url: string): Promise<void>;
  send(itemId: bigint, payload: Uint8Array): Promise<void>;
  sendBatch(items: BatchItem[]): Promise<void>;
  recv(timeoutMs: number): Promise<Record | null>;
  close(): Promise<void>;
}

export interface PulzzConfig {
  carrier: CarrierKind;
  security: SecurityProfile;
  batchSize?: number;        // 0 = per-item, >0 = batch
  zstdLevel?: number;        // 0 = disabled (WASM default)
  timeoutMs?: number;
}

export enum CarrierKind {
  WebSocket = 0,
  WebTransport = 4,
}

export enum SecurityProfile {
  PqMutualV1 = 0,    // not available in WASM (requires x25519-dalek)
  PqSimpleV1 = 1,    // ML-KEM-768 only — default for WASM
  ClassicRef1 = 2,
}

export interface BatchItem {
  itemId: bigint;
  sourceKind: SourceKind;
  payload: Uint8Array;
}

export interface Record {
  itemId: bigint;
  payload: Uint8Array;
}
```

### 7.2 WASM limitations

- **Carriers**: only `WebSocket` and `WebTransport` (no raw TCP/QUIC/UDP in browser)
- **Security**: only `PqSimpleV1` (ML-KEM-768; the full `PqMutualV1` requires x25519-dalek which is native-only)
- **Compression**: disabled (zstd-sys requires clang for wasm32). The batch envelope still works; payloads are uncompressed.
- **Async**: uses `wasm-bindgen-futures` for Promise-based API

### 7.3 Usage example

```javascript
import { PulzzClient, CarrierKind, SecurityProfile } from 'pulzz';

const client = new PulzzClient({
  carrier: CarrierKind.WebSocket,
  security: SecurityProfile.PqSimpleV1,
  batchSize: 50,
});

await client.connect('wss://example.com/pulzz');

// Send single
await client.send(1n, new Uint8Array([1, 2, 3]));

// Send batch
await client.sendBatch([
  { itemId: 1n, sourceKind: 1, payload: new Uint8Array([1]) },
  { itemId: 2n, sourceKind: 1, payload: new Uint8Array([2]) },
]);

// Receive
const record = await client.recv(5000);
if (record) {
  console.log(`got item ${record.itemId}: ${record.payload.length} bytes`);
}

await client.close();
```

### 9.1 Go API

```go
package main

import "github.com/pkhairkh/pulzz/bindings/go"

func main() {

        Carrier:   pulzz.CarrierWebSocket,

    if err != nil { panic(err) }

        panic(err)

        {ID: 2, SourceKind: pulzz.SourceJSON, Payload: []byte(`{"user":"bob"}`)},
    })

}
```

## 12. Implementation plan

### Phase 1: Rust SDK crate (1-2 days)
- `sdk/` crate with `PulzzClient`, `PulzzServer`, `BatchBuilder`
- Wraps existing `client::ClientSession` and `server::ServerSession`
- Builder pattern for config
- Async API using Tokio

### Phase 2: C ABI crate (2-3 days)
- `ffi/` crate with `extern "C"` functions
- `cbindgen` for header generation (`pulzz.h`)
- Opaque handle types, `pulzz_result_t` error codes
- Thread-local error string for `pulzz_last_error()`
- No panics across FFI (catch_unwind on every function)

### Phase 3: WASM/JS binding (1-2 days)
- `bindings/wasm/` crate with `wasm-bindgen`
- Expose `PulzzClient` to JS
- `wasm-pack build` produces `pulzz.wasm` + `pulzz.js`
- Limit carriers to WebSocket + WebTransport

### Phase 4: Python binding (1-2 days)
- `bindings/python/` crate with `PyO3`
- `maturin develop` for local testing
- `maturin publish` for PyPI

### Phase 5: Go binding (1 day)
- `bindings/go/pulzz.go` with cgo
- Wraps `libpulzz` shared library
- `go get github.com/pkhairkh/pulzz/bindings/go`

### Phase 6: Examples + docs (1 day)
- `examples/sdk_usage.rs`, `examples/c_example.c`, `examples/js_example.js`, `examples/python_example.py`
- SDK docs in `docs/sdk.md`

**Total: ~7-11 days**

## 13. Testing strategy

- **Rust SDK**: integration tests using the existing eval harness
- **C ABI**: property tests (round-trip, fuzz) + valgrind for memory safety
- **WASM/JS**: `wasm-pack test --node` for Node.js, headless browser for browser
- **Python**: pytest with same test vectors
- **Go**: `go test` with same test vectors
- **Cross-language**: a test suite that sends from Rust and receives in JS/Python/Go, verifying wire compatibility

## 14. Versioning

- **Rust crate**: SemVer (`0.3.0` → `0.4.0` → `1.0.0`)
- **C ABI**: `pulzz_abi_version()` returns packed u32. Breaking ABI changes bump the major version. The C header uses `#if` guards for version-dependent features.
- **Wire protocol**: `PROTOCOL_VERSION = 2` (in `shared_protocol/src/protocol.rs`). Wire-format changes require a version bump.
- **Bindings**: each follows its language's convention (npm SemVer, PyPI SemVer, Go module tags)

## 16. Open questions

1. **Should the C ABI expose the PST/UCB1 predictor state?** Currently these are internal to the server. The SDK could expose `pulzz_client_set_prediction_confidence_threshold()` for advanced users.
2. **Should the Python binding use PyO3 or cffi?** PyO3 is more idiomatic but requires compilation per Python version. cffi wraps the C ABI directly and is more portable but less ergonomic.
3. **Should the Go binding use cgo or a pure-Go reimplementation?** cgo is faster to implement; pure-Go is more portable but requires reimplementing the PQC crypto (which defeats the purpose of "one wire, many bindings").
4. **Mobile (Android/iOS)**: should we target these in v1, or defer? The C ABI works on both, but the JNI/Swift wrappers add complexity.

---

## 17. Recommendation

Start with **Phases 1-3** (Rust SDK + C ABI + WASM/JS). These cover the primary deployment targets (browser clients + native servers) and can be done in ~5 days. Python and Go bindings can follow in a second sprint.

The C ABI is the keystone — once it's stable, every other binding is a thin wrapper. Invest in getting the C ABI right: opaque handles, explicit lifetimes, no panics, clear error codes.
